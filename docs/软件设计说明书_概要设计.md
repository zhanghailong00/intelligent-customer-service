## 1. 引言

### 1.1 项目背景
随着业务规模扩大，技术支持团队面临以下挑战：

| 痛点 | 影响 |
|------|------|
| 重复性咨询 | 技术人员反复回答相同的产品参数、使用方法等问题 |
| 服务时效性差 | 高校老师在非工作时间遇到问题无法及时获得帮助 |
| 培训资料分散 | 产品手册、实验指导书等资料散落各处，查找困难 |

| 增加AI客服系统 | AI，大模型等技术关联作为亮点 |

### 1.2 项目目标

构建基于多智能体架构的智能客服系统，实现：

- **7×24小时自动响应**：覆盖产品咨询、故障排查、培训资料三大场景
- **智能路由分发**：根据用户意图自动分配给专业领域 Agent 处理
- **知识库管理**：支持非技术人员通过 Web 界面动态更新知识库
- **人机协作**：复杂问题自动转交人工客服，确保服务质量

### 1.3 术语定义

| 术语 | 说明 |
|------|------|
| Agent | 智能体，能够自主完成特定任务的 AI 单元 |
| RAG | 检索增强生成，结合知识库检索与 LLM 生成 |
| LangGraph | LangChain 生态的状态图框架，用于编排 AI 工作流 |
| HITL | 人机协作，AI 无法处理时自动转人工 |
| Embedding | 文本向量化，将文字转换为数学向量表示 |

## 2. 业务场景

### 2.1 用户角色

| 角色 | 描述 | 典型问题 |
|------|------|----------|
| **高校教师** | 任课教师、实验室主任 | 产品参数、故障排查、教学资料 |
| **学生** | 实验课程学生 | 实验步骤、设备问题 |
| **技术支持** | 公司技术人员 | 处理 AI 无法解决的复杂问题 |
| **知识管理员** | 产品/培训部门人员 | 维护和更新知识库 |

### 2.2 核心业务场景

#### 场景一：售前产品咨询

**典型问题**：
- "这款实训箱有哪些模块？"
- "实训箱支持哪些通信协议？"

**处理流程**：
```
用户提问 → 意图识别（产品咨询）→ 产品专家 Agent → 知识库检索 → 生成回答
```

#### 场景二：售后故障排查

**典型问题**：
- "传感器不亮了怎么办？"
- "WiFi模块连不上网，怎么排查？"
- "程序下载失败，提示连接错误"

**处理流程**：
```
用户提问 → 意图识别（故障排查）→ 技术支持 Agent → 知识库检索 → 思维链推理 → 生成回答
```

#### 场景三：培训资料查询

**典型问题**：
- "有没有智能家居的实验指导书？"
- "怎么做温湿度传感器实验？"

**处理流程**：
```
用户提问 → 意图识别（培训资料）→ 培训顾问 Agent → 知识库检索 → 生成回答
```

## 3. 系统功能

### 3.1 功能模块

```
嵌入式实训箱智能客服系统
├── 1. 用户交互模块
│   ├── 文本输入/输出
│   ├── 流式输出（逐字显示）
│   └── 会话历史管理
│
├── 2. 智能路由模块
│   ├── 意图分类（产品/故障/培训/打招呼/未知）
│   └── 路由分发
│
├── 3. Agent 集群模块
│   ├── 产品专家 Agent
│   ├── 技术支持 Agent
│   └── 培训顾问 Agent
│
├── 4. 查询重写模块
│   ├── 历史对话上下文感知
│   └── 查询改写（提升检索效果）
│
├── 5. 知识库模块
│   ├── 文档管理（上传/删除/更新）
│   ├── 向量化存储
│   └── 语义检索
│
└── 6. 人机协作模块（HITL）
    ├── 质量检测
    ├── 转人工触发
    └── 会话快照
```

### 3.2 核心功能说明

#### 3.2.1 智能路由

基于 LLM 的意图识别，将用户问题自动分类为 5 种意图：

| 意图类型 | 触发条件 | 路由目标 | 后续处理 |
|----------|----------|----------|----------|
| **product** | 询问参数、功能、配置 | 产品专家 Agent | → HITL 检测 |
| **fault** | 设备故障、软件报错 | 技术支持 Agent | → HITL 检测 |
| **training** | 实验指导、课件、教程 | 培训顾问 Agent | → HITL 检测 |
| **greeting** | 问候语、开场白 | 友好回复 + 功能引导 | → 直接结束 |
| **unknown** | 无法识别或超出范围 | 礼貌拒绝 + 建议转人工 | → 直接结束 |

#### 3.2.2 三大 Agent

**产品专家 Agent**
- 角色：产品知识专家
- 职责：产品参数、功能介绍、配置对比
- 策略：角色扮演 + 少样本提示 + 拒绝策略

**技术支持 Agent**
- 角色：技术支持工程师
- 职责：设备故障、软件报错、接线问题
- 策略：角色扮演 + 少样本提示 + 拒绝策略 + 思维链（CoT）

**培训顾问 Agent**
- 角色：培训顾问
- 职责：实验指导、课件推荐、教学资料
- 策略：角色扮演 + 少样本提示 + 拒绝策略

#### 3.2.3 查询重写

在 RAG 检索前改写用户问题，提升检索效果：

- **历史感知**：传入最近 3 轮对话历史，理解多轮对话中的代词和指代
- **上下文补充**：补充缺失的设备名称、场景等信息
- **关键词扩展**：让问题更具体，提升检索召回率
- **降级机制**：改写失败时返回原始 query

#### 3.2.4 人机协作（HITL）

当 AI 无法独立完成任务时，自动转交人工客服：

**触发条件**：

| 触发场景 | 检测方式 |
|----------|----------|
| Agent 明确拒绝 | 回复包含"我不确定"、"建议联系技术支持" |
| 用户主动要求 | 用户说"转人工"、"找客服" |
| 置信度低 | 意图分类置信度 < 0.5 |
| 敏感问题 | 涉及退款、投诉等关键词 |

**人工转接流程**：

```
用户在网址提问
      ↓
AI 无法回答
      ↓
生成会话链接：https://chat.com/session/abc123
      ↓
企业微信通知客服（带链接）
      ↓
客服点击链接，打开网址
      ↓
客服在网址上查看对话历史
      ↓
客服在网址上回复用户
      ↓
用户在网址上看到客服回复
```

**客服管理后台**：

| 页面 | 功能 |
|------|------|
| `/admin/login` | 客服登录（用户名密码） |
| `/admin` | 会话列表（显示待处理会话） |
| `/admin/session/{id}` | 会话详情（对话历史 + 回复输入框） |

#### 3.2.5 图片支持（图文混排）

**目标**：回答中包含文档图片，让用户更直观

**图片存储**：

```
knowledge/
├── images/          ← 所有图片统一存放
│   ├── products/    ← 产品相关图片
│   └── training/    ← 培训相关图片
└── products/        ← Markdown 文档
    └── manual.md    ← 引用：../images/products/xxx.png
```

**实现方式**：

- 知识库导入时记录图片路径
- RAG 检索返回文字 + 图片
- Gradio 界面支持图文混排显示

**示例**：

```
用户提问："传感器怎么接线？"

回答：
传感器接线步骤如下：

![接线图](../images/wiring_diagram.png)

1. 将 VCC 接到 3.3V
2. 将 GND 接到地
3. 将 DATA 接到 PA1

![引脚图](../images/pin_diagram.jpg)
```

### 4.2 数据流向

```
用户提问
    ↓
查询重写（基于历史对话上下文，LLM 改写为专业术语）
    ↓
向量检索（ChromaDB，Top-K 相关文档）
    ↓
LLM 生成回答（结合检索结果 + 对话历史 + Agent Prompt）
    ↓
质量检测（HITL，检查是否需要人工介入）
    ↓
返回用户
```

### 4.3 LangGraph 状态图

```
START
   ↓
classifier_node（意图分类）
   ↓
┌─────────────────────────────────────────────────────────┐
│                    条件路由                              │
├─────────────┬─────────────┬─────────────┬─────────────┤
│  greeting   │   unknown   │   product   │    fault    │
│    node     │    node     │    node     │    node     │
│             │             │      +      │      +      │
│             │             │ training    │   hitl      │
│             │             │    node     │  checker    │
└──────┬──────┴──────┬──────┴──────┬──────┴──────┬──────┘
       ↓             ↓             ↓             ↓
      END           END      hitl_checker     END
                               _node
                                 ↓
                                END
```

**状态字段**：
- `messages`：对话历史（LangGraph 自动管理）
- `intent`：意图类型（product/fault/training/greeting/unknown）
- `confidence`：意图分类置信度
- `role_name`：Agent 身份名称（产品专家/技术支持/培训顾问）
- `answer`：生成的回答
- `sources`：参考来源
- `hitl_required`：是否需要人工介入

## 5. 技术选型

### 5.1 核心技术栈

| 层次 | 技术 | 版本 | 选型理由 |
|------|------|------|----------|
| 编程语言 | Python | 3.10+ | AI/ML 生态成熟 |
| Web 框架 | FastAPI | 0.100+ | 异步支持、自动文档生成 |
| 前端界面 | Gradio | 4.0+ | 快速原型、Python 原生 |
| AI 框架 | LangChain | 1.0+ | RAG 生态完善 |
| 状态图引擎 | LangGraph | 1.0+ | 支持 HITL interrupt |
| 向量数据库 | ChromaDB | 0.4+ | 纯 Python、零配置 |
| 关系数据库 | SQLite | — | 轻量级、无需额外服务 |
| LLM 服务 | DeepSeek API | — | 中文效果好、成本低 |
| Embedding | 通义千问 | v3 | 中文向量化效果优秀 |

### 5.2 选型决策树

```
需要 LLM 服务？
├── 数据敏感 / 需要私有化 → Ollama 本地部署（需 GPU 服务器）
└── 数据可上云 / 快速开发 → DeepSeek API

需要向量数据库？
├── 数据量 > 100 万条 → Milvus（分布式，需额外部署）
└── 数据量 < 10 万条 → ChromaDB

需要 Embedding？
├── 数据敏感 → BGE 本地部署（需 GPU 服务器）
└── 数据可上云 → 通义千问 API
```

### 5.3 关键选型对比

#### LLM 服务对比

| 维度 | DeepSeek API | Ollama 本地 | OpenAI API |
|------|--------------|-------------|------------|
| **成本** | 低（按 token 计费） | 无（需 GPU 服务器） | 高 |
| **中文效果** | 优秀 | 取决于模型选择 | 一般 |
| **部署难度** | 低（API 调用） | 高（需 GPU、运维） | 低（API 调用） |
| **数据安全** | 数据上云 | 数据私有 | 数据上云 |
| **响应速度** | 快 | 快（本地） | 中等 |

#### 向量数据库对比

| 维度 | ChromaDB | Milvus | Weaviate |
|------|----------|--------|----------|
| **部署方式** | 嵌入式（零配置） | 分布式（需部署） | 单机/集群 |
| **学习成本** | 低 | 中 | 中 |
| **性能** | 中等 | 高 | 高 |
| **适用规模** | < 10 万条 | > 100 万条 | 中大 |

## 8. 风险与对策

### 8.1 技术风险

| 风险 | 对策 |
|------|------|
| LLM API 不稳定 | 实现重试机制、降级到其他模型 |
| 检索效果不佳 | 优化查询重写、调整检索参数 |
| 响应时间过长 | 异步处理、缓存热门问答 |

### 8.2 项目风险

| 风险 | 对策 |
|------|------|
| 知识库内容不足 | 分阶段补充，先覆盖高频问题 |
| 预算超支 | 控制 API 调用成本，优化调用频率 |
