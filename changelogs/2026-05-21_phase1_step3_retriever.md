## 每个文件的改动详情

### app/rag/retriever.py（重写）

**功能**：基于向量相似度的文档检索

**核心函数**：
- `get_query_embedding(text)`: 使用通义千问 API 获取查询向量
- `get_vectorstore()`: 获取 ChromaDB 实例
- `retrieve(query, top_k, filters, include_scores)`: 检索相关文档
- `retrieve_with_context(query, top_k)`: 检索并格式化为 RAG 上下文
- `get_retrieval_stats()`: 获取统计信息

**关键改进**：
1. **查询向量化一致性**：查询时使用通义千问 API 向量化（768 维），与存储时保持一致
   - 解决了维度不匹配问题（之前 ChromaDB 默认用本地 ONNX 模型 384 维）
2. **返回完整信息**：返回文档内容 + 元数据 + 相似度分数
3. **相似度阈值**：过滤低于 0.5 的低质量结果
4. **元数据过滤**：支持按来源、章节等过滤
5. **格式化上下文**：`retrieve_with_context()` 直接生成 RAG 可用的上下文字符串

**为什么这样设计**：
- 使用在线 Embedding 保证向量维度一致
- 相似度阈值避免返回无关内容
- 格式化上下文方便后续 RAG 问答链使用

## 潜在风险

| 风险 | 说明 | 缓解措施 |
|---|---|---|
| API 调用延迟 | 每次查询需要调用 Embedding API | 可考虑缓存热门查询 |
| 相似度阈值 | 阈值过高可能漏掉相关结果 | 默认 0.5，可根据效果调整 |
| 网络不稳定 | Embedding API 调用失败 | 已添加异常处理 |
