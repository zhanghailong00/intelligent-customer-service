## 问题背景（Bug 描述）

**现象**：用户说"转人工"时，系统返回"抱歉，您的问题似乎与实训设备无关"

**根因分析**：

```
用户说"转人工"
    ↓
classifier_node 调用 LLM 意图分类
    ↓
LLM 将"转人工"分类为 intent=unknown（30% 置信度）
    ↓
route_by_intent 路由到 unknown_node
    ↓
unknown_node 返回通用回复（不相关问题）
    ↓
hitl_checker_node 从未被执行（因为 unknown_node 直接到 END）
```

**根本原因**：HITL 检测仅在 Agent 节点后执行（后置检测），但"转人工"被分类为 unknown，走了 greeting/unknown 专用路径，跳过了 Agent → hitl_checker 链路。

---

## 修复方案：前置+后置双层 HITL 架构

### 修改前

```
classifier_node（仅 LLM 分类）
    ↓
agent → hitl_checker（仅后置检测）
```

问题：系统控制意图（转人工、投诉）被业务分类器吞掉。

### 修改后

```
classifier_node（前置规则检测 + LLM 分类）
    ├── 命中系统控制词 → 直接返回提示（不调用 LLM）
    └── 未命中 → 正常 LLM 分类
         ↓
    agent → hitl_checker（后置兜底保留）
```

### 设计原则

| 层级 | 检测方式 | 覆盖场景 | 优先级 |
|------|---------|---------|--------|
| 前置检测 | 规则匹配 | 转人工、投诉、售后 | 最高（路由前拦截） |
| 后置检测 | 规则匹配 | Agent 拒绝、低置信度 | 兜底（Agent 执行后） |

## 面试亮点

### 1. 从 Bug 到架构重构的完整过程

发现问题 → 分析根因 → 设计方案 → 实现修复 → 文档记录

### 2. 双层 HITL 架构

- 前置检测：系统控制意图，规则匹配，毫秒级响应
- 后置检测：Agent 失败兜底，确保不遗漏

### 3. 系统控制意图 vs 业务意图分离

- 系统控制意图：转人工、投诉 → 规则匹配，优先级最高
- 业务意图：产品、故障、培训 → LLM 分类

### 4. 为什么规则匹配优于 LLM 分类（针对系统意图）

- 确定性：同样输入同样结果，不波动
- 速度：毫秒级，不消耗 LLM token
- 可调试：看到关键词就知道为什么命中
