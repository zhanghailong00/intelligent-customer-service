## 设计决策

### 为什么需要会话快照？

原始 HITL 流程只告诉用户"正在转接"，但人工客服接手时不知道：
- 用户到底要解决什么问题
- AI 为什么处理不了
- 该怎么接手处理

会话快照解决了这个问题，实现**无缝接力**。

### 快照数据流程

```
State（answer/messages/sources/confidence）
    ↓ 从 State 读取原始数据
LLM（DeepSeek）分析对话
    ↓ 生成核心诉求 + 建议方案
快照展示在前端
```

### 快照字段设计

| 字段 | 来源 | 必要性 |
|------|------|--------|
| 核心诉求 | LLM 从 State 对话历史中提取 | 必须 — 5 秒了解情况 |
| 转人工原因 | detector 函数检测结果 | 必须 — 知道为什么转来 |
| 建议方案 | LLM 根据 State 数据生成 | 必须 — 知道下一步做什么 |
| 对话历史 | State messages | 必须 — 需要时查看细节 |

**去掉了**：情绪判断、优先级、设备识别（从对话历史中可直接获取，单独提出来冗余）

### 人工接管模式

HITL 触发后，**所有后续消息都由人工客服处理**，直到人工说"关闭"：

```
用户提问 → HITL 触发 → 显示快照
    ↓
人工回复 → "[人工客服] xxx"（所有后续消息走人工）
人工回复 → "[人工客服] xxx"
人工说"关闭" → 退出人工模式，恢复 AI
```

### LLM 调用策略

- 一次调用同时输出核心诉求 + 建议方案（减少 API 调用）
- temperature=0.3（低温度，确保输出稳定）
- 降级机制：LLM 调用失败时返回基础快照

## Bug 修复：快照不显示

### 问题现象

会话快照在后端生成成功（`[HITL] 会话快照生成成功`），但 Gradio 前端没有展示。

### 根因分析

LangGraph `interrupt()` 机制：图执行暂停时，**不抛异常**，而是正常返回。但 `hitl_checker_node` 的返回值（`hitl_required=True`）**没有合并到 state**，因为图在 interrupt 点暂停，节点的返回值被丢弃。

```
graph.invoke() → hitl_checker_node 调用 interrupt() → 图暂停 → 返回当前 state
                                                              ↑
                                              hitl_required 仍为 False（初始值）
```

### 修复方案

将 HITL 检测逻辑从 graph 内部移到 web 层：

| 修改前 | 修改后 |
|--------|--------|
| 检测 `result["hitl_required"]` | 检查 Agent 回答中的拒绝关键词 |
| 依赖 graph state | 直接调用 detector 函数 |
| 永远是 False | 正确检测到 HITL |

```python
# web/app.py — 在前端层检测 HITL
answer = result.get("answer", "")
if check_agent_refusal(answer):
    hitl_reason = "Agent 拒绝回答"
elif check_low_confidence(confidence):
    hitl_reason = "置信度低"
```

## 面试亮点

1. **会话快照设计**：从 State 读取原始数据 → LLM 生成结构化快照 → 前端展示，实现无缝接力
2. **人工接管模式**：HITL 触发后人工完全接管，说"关闭"才恢复 AI，符合真实客服场景
3. **LLM 在 HITL 中的应用**：不只是问答，还能做信息提取和分析（核心诉求+建议方案）
4. **降级机制**：LLM 失败时优雅降级，不影响核心流程
5. **字段精简**：从人工客服实际工作流程出发，只保留 4 个核心字段
